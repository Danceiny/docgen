# Changelog

All notable changes are listed here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project follows
[Semantic Versioning](https://semver.org/), with the caveat that before 1.0 the
command line, the configuration and the output can change in a minor version.
The generated documents of a version do not change within it.

## [Unreleased]

### Added

- The first public version: `docgen` generates OpenAPI 3.0 documents from the Go
  source of a module, for an internal and a public audience, as configured by
  `docgen.yaml`, with overlay files and an error catalog.
- `docgen -check` to verify in CI that checked-in documents are current.
- The package `route`, the specification of the route convention.
- `examples/petstore`, a module that exercises most of the tool.
- Diagnostics for the mistakes that make something disappear without a word:
  a configuration key that does not exist, or names a type the module does not
  declare, a package pattern that matches nothing, an annotation or an `//apidoc:`
  directive that is mistyped or cannot be read, an `apidoc:"..."` tag value that
  hides a field, a second parameter that is not in the document, enum values that
  name no constant.
- `compat.legacy_operation_types` and `compat.legacy_schema_shapes`, which keep
  the reading of documents generated by the tool docgen began as (see the README).
  Without them: a list, a map or an instantiated generic type is the result or
  the request it is; every name of a declaration of several is a field; an
  embedded struct with a json name is a field; `required` among the rules of a
  `validate` or `binding` tag makes a field required; `any` and `interface{}`
  take any JSON value; enum values are the ones the compiler computes; the values
  of a map are described; a slice of bytes is a base64 string.

### Known limitations

These are the behaviour of the first version; each is a candidate for a later
release.

- A type of another module is written out where it is used, not made a component,
  and when it contains itself it is an `object` the second time; a custom marshaler
  is not read.
- A public document writes the types that fields use in place, and only the types
  that operations take or return are components.
- `json:",string"` is ignored, a pointer is not nullable unless `json:"x,nullable"`
  says so, and `json.RawMessage` is a `string`.
- A generic type is documented as declared; the fields of a type-parameter type
  have no schema and only one type parameter is supported.
- Query parameters are listed by hand in `request.query`.
- The comment of a type is not its description; the internal document drops the
  comment of a field that is a `$ref`.
- An operation whose request or response type is declared outside the packages
  that `models` matches makes the run fail.
